Layer 04 · Capability
08 / 18
第 4 层

能力集成层

Agent 的能力不是写死的工具箱，而是按 appId 装配、按对话需要激活的运行时组合。

AgentScope
把 ReActAgent 与 Session Provider 组合成可运行实体。
SkillBox
技能从数据库发布，并按应用维度装配。
Toolkit
睡眠、饮食、用户画像等业务工具进入 Agent 能力面。
Lazy Activation
对话中根据意图延迟激活，而不是每轮全量暴露。
Evidence: AgentFactory · AgentSkillService · SleepHealthTool · AgentScopeSessionConfig

Judgement 02 · Session Custody
12 / 18
核心架构判断 2

它是会话托管型 Agent。

业务层没有自己拼 history 作为全部上下文，而是把真实会话状态交给 AgentScope Session 承载。

Business Layer
维护活跃会话映射、处理入口身份和持久化日志。
AgentScope Session
承载真实对话状态，是 Agent 运行时的一部分。
Provider Choice
Memory 或 Redis 的选择直接影响生产部署形态。
评审重点：Session Provider 不是实现细节，它决定多副本时是否串会话、丢上下文或难以横向扩展。

Production Risks · Required Changes
16 / 18
上线前必须处理

部署风险不是边角料。

P0 Session
生产必须从 memory 切到 Redis Session，否则多实例会串会话或丢上下文。
P0 Secret
模型和 Mem0 明文配置必须迁移到环境变量或 Secret Manager。
P1 Stateless
Spring Boot 节点只做编排，本地不保存不可恢复会话状态。
P1 Model Scale
模型网关或 vLLM 集群独立扩缩容，避免长推理拖垮 API。
Evidence: application.yml:1 · AgentScopeSessionConfig.java:33

17 / 18
测试补充

测试失败
不推翻架构判断。

mvn test 的失败点主要落在 Java 25 与 Mockito / ByteBuddy 版本兼容性，而不是这次架构分层判断本身。

Observed Failure
Mockito / ByteBuddy 对 Java 25 的支持问题导致测试运行失败。
Architecture Impact
不影响代码实态中对接入、编排、认知、能力、基础设施的识别。
Follow-up
升级测试依赖或固定 JDK 版本后，再补跑完整单元与集成测试。

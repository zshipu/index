Codex 2026 最新实战指南

2026年8月14日
| 阅读

从GPT-5.6 到 Agent Skills

一、Codex 一年进化史：从 CLI 到智能体平台

先快速回顾一下 Codex 这一年多都发生了什么，帮你建立时间线概念：

2025 年 4 月 — Codex CLI 开源发布（Rust 编写，Apache-2.0 协议），跑在终端里，能读代码库、改文件、跑命令。

2025 年 5 月 — Codex Cloud 研究预览版上线，基于 codex-1 模型（o3 针对软件工程微调），能在云端沙箱里并行跑多个任务。

2025 年 9 月 — GPT-5-Codex 发布，CLI 全面重构，新增图片输入、任务列表、联网搜索、MCP 连接、上下文压缩。IDE 扩展同步上线，支持 VS Code / Cursor / Windsurf。

2025 年 10 月 — Codex 正式 GA（Generally Available），新增 Slack 集成、TypeScript SDK、GitHub Action。从此 Codex 不只是个人工具，团队也能用了。

2025 年 11 月 — GPT-5.1-Codex 系列发布（标准版 + Mini + Max）。Max 是第一个支持跨上下文窗口工作的模型，能跑多小时级的长任务。

2025 年 12 月 — GPT-5.2-Codex 发布 + Agent Skills 上线。Skills 让 Codex 能复用工作流，像装插件一样扩展能力。

2026 年 2 月 — Codex 桌面 App 在 macOS 上线，GPT-5.3-Codex 和 Codex-Spark 发布。Spark 是第一个实时编码模型，速度超过 1000 tokens/秒。

2026 年 3 月 — Codex App 登陆 Windows，GPT-5.4 上线，Codex Security 进入研究预览。实验性支持 100 万 token 上下文窗口。

2026 年 4 月 — GPT-5.5 成为推荐默认模型，新增浏览器操控能力（能点击 UI、复现视觉 bug）。

2026 年 5 月 — Codex for Chrome 浏览器扩展发布，移动端预览上线，支持 Remote SSH。

2026 年 6 月 — Sites 功能上线（能从 Codex 直接创建和托管网站），Codex Remote 正式 GA。

2026 年 7 月 — GPT-5.6 发布（Sol / Terra / Luna 三档模型），Codex 正式合并进 ChatGPT 桌面端。Codex Security CLI 开源。语音控制上线。

一年时间，Codex 从一个终端工具变成了覆盖 CLI、IDE、桌面 App、云端、移动端、浏览器扩展的全平台智能体系统。底层模型也从 codex-1 迭代到了 GPT-5.6。

二、GPT-5.6 三档模型怎么选？

2026 年 7 月发布的 GPT-5.6 把模型分成了三档，选对了能省额度、提效率：

- Sol：最强档，专门打硬仗。大型重构、复杂架构变更、安全审计这类需要深度推理的任务用它。支持 ultra 模式，会调用子代理并行加速。

- Terra：平衡档，能力和成本兼顾。日常开发、写功能代码、修 bug、写测试用它最合适。免费和 Go 用户默认用 Terra。

- Luna：速度档，快且便宜。代码探索、文件审查、处理文档这类轻量任务用它。Token 消耗更少，适合批量跑子代理任务。

切换方法：

# CLI 里指定模型

codex –model gpt-5.6-sol “重构认证模块”

codex –model gpt-5.6-terra “修复这个bug”

codex –model gpt-5.6-luna “总结这个项目结构”

# 或者会话中切换

/model gpt-5.6-sol

实用建议：日常用 Terra，重活切 Sol，轻活用 Luna。额度紧张时多用 Luna 能多干 3 倍的活。

三、安装与登录：2026 最新版

安装命令没变，还是一行：

npm install -g @openai/codex

但登录方式有了大变化。现在支持两种方式：

方式一：ChatGPT 账号登录（推荐）

codex login

直接用你的 ChatGPT Plus / Pro / Team 订阅，不需要单独买 API Key。额度走 ChatGPT 套餐。

方式二：API Key 登录

在配置文件 ~/.codex/config.toml 里设置：

preferred_auth_method = “apikey”

适合需要精确控制成本、走企业报销的场景。两种方式可以随时切换，一种额度用完了切另一种就行。

Windows 用户：现在 Codex 桌面 App 已经原生支持 Windows 了（2026 年 3 月上线），不需要再用 WSL。但如果你习惯 Linux 工具链，也可以在 App 里选择 WSL 环境。

四、2026 年必须知道的 10 个新能力

1. Agent Skills：可复用的工作流

这是 2025 年 12 月上线的功能，现在已经成为 Codex 的核心扩展机制。Skills 就像是给 Codex 装的技能包，每个 Skill 包含一组指令和可选的脚本、资源文件。

用法很简单：

# 在会话中直接调用

$skill-installer

$create-plan

# 让 Codex 自动选择合适的 Skill

codex “帮我补单测到90%覆盖率”

Skill 文件结构遵循开放的 agentskills.io 标准：

my-skill/

SKILL.md # 必需：指令和元数据

scripts/ # 可选：可执行代码

references/ # 可选：文档

assets/ # 可选：模板和资源

安装位置：个人用放在 ~/.codex/skills/，团队共享放在项目的 .codex/skills/ 里。

2. Codex 合并进 ChatGPT

2026 年 7 月起，Codex 不再是独立 App，而是合并进了 ChatGPT 桌面端。之前的 Codex App 用户更新到最新版 ChatGPT 就能自动迁移，项目、设置、工作流都保留。

同时新增了：内联 diff 编辑、侧边栏 PR 审查、跨仓库项目管理。

3. 浏览器操控

Codex 现在能操作内置浏览器了。它能点击 UI、导航页面、复现视觉 bug、验证本地修复。适合前端开发和调试场景。

通过内置的 Browser 插件运行，在设置里可以管理允许或禁止访问的网站。

4. 语音控制

2026 年 7 月 23 日上线。你可以用语音指挥 Codex 干活，同时控制多个代理并行运行。适合在移动场景下使用（比如走路时口头下达任务）。

5. Codex Security

OpenAI 把原来的 Aardvark 安全代理改名为 Codex Security，2026 年 3 月进入研究预览，7 月开源了 CLI 和 SDK。它能：

- 为代码库构建威胁模型

- 在隔离环境中验证漏洞

- 自动提出修复补丁供人工审查

适合有安全审计需求的团队。

6. Codex Remote（手机控制电脑）

2026 年 6 月正式 GA。扫码配对手机和电脑后，可以用手机启动任务、查看进度、审批操作、切换模型。文件和执行环境都留在电脑上，手机只负责状态同步。

7. Codex for Chrome

浏览器扩展，能让 Codex 操作已登录的浏览器页面，跨标签页后台工作。你控制哪些网站对 AI 开放。

8. codex resume：恢复中断的会话

2025 年 10 月新增。之前会话断了就得重来，现在一行命令恢复：

codex resume

配合自动上下文压缩（接近上下文窗口限制时自动总结），长会话体验好了很多。

9. Programmatic Tool Calling

GPT-5.6 的隐藏大杀器：模型可以写 JavaScript 在隔离的 V8 运行时里协调多个工具调用，而不是把中间结果反复传回上下文窗口。

效果：多步骤工作流的往返次数大幅减少，token 消耗显著降低。搜索代码库、聚合测试结果、过滤 API 响应这类任务尤其受益。

10. Sites：从 Codex 直接发布网站

2026 年 6 月上线。Codex 能直接创建和托管网站、仪表盘、内部工具、Web 应用甚至小游戏，生成后可通过 URL 分享。适合快速做原型和内部工具。

五、实战技巧：2026 年版 CLI 速查

技巧 1：用 /plan 先规划再动手

跨文件改动、重构、排障之前，先让 Codex 出方案：

/plan 把 Express 路由迁移到 Hono

它会列出涉及哪些文件、验证命令和潜在风险。你确认后再让它执行，减少跑偏。

技巧 2：四段式 Prompt 写法

OpenAI 官方推荐的 prompt 结构：

Goal: 把 user router 从 Express 迁移到 Hono

Context: src/routes/user.ts, middleware/auth.ts, test/user.test.ts

Constraints: 不引入新依赖版本大跳; JWT 逻辑保持不变

Done when: pnpm test 全绿, pnpm start 返回 200, 旧入口删除

规则越像给新人工程师的 onboarding 文档，Codex 越像 senior。

技巧 3：AGENTS.md 仍然是基础

在项目根目录放 AGENTS.md，告诉 Codex 项目规范：

# AGENTS.md

- 新文件统一用 TypeScript

- 函数名 camelCase, 组件用 PascalCase

- 测试框架用 Jest

- 不要动 src/legacy 目录

- 完成标准: test 全绿 + lint 零错

技巧 4：codex exec 用于 CI/CD

非交互模式，适合自动化流水线：

# 修复所有失败的测试

codex exec “fix all failing tests”

# JSON 输出 + 保存结果 + 工作区沙盒

codex exec –json –output-last-message result.txt \

--sandbox workspace-write “fix CI failure”

# 附带截图做多模态分析

codex exec –image screenshot.png “explain this architecture”

技巧 5：模型切换策略

# 重活用 Sol

codex –model gpt-5.6-sol “重构整个认证系统”

# 日常用 Terra

codex –model gpt-5.6-terra “修复登录页bug”

# 轻活用 Luna（省额度）

codex –model gpt-5.6-luna “总结最近10次提交”

# 用 Spark 做实时编码（Pro 用户）

codex –model gpt-5.3-codex-spark “快速生成CRUD接口”

技巧 6：常用斜杠命令

- /plan — 先出方案再执行

- /diff — 看 Codex 实际改了什么

- /model — 运行中切换模型

- /permissions — 调整审批策略（read-only / auto / full-access）

- /compact — 压缩上下文

- /status — 查看 token 用量

- /fix — 自动修复语法错误

- /test — 为函数生成测试用例

- /doc — 为函数生成文档注释

技巧 7：Team Config 团队配置共享

2026 年 1 月上线。在 .codex/ 目录放共享配置，团队成员自动继承：

.codex/

config.toml # 默认配置

rules/ # 命令控制规则

skills/ # 可复用工作流

支持多层级覆盖：当前目录 > 父目录 > 仓库根 > 用户级 > 系统级。管理员用 requirements.toml 强制约束。

六、四端一体：哪里都能用

2026 年的 Codex 已经不是只有 CLI 了，而是四端打通：

- CLI（开源）：终端原住民首选，codex 命令直接开干

- IDE 扩展：VS Code / Cursor / Windsurf / JetBrains 都支持，inline / chat / agent 三模式

- ChatGPT 桌面端（原 Codex App）：可视化指挥台，多项目并行，后台 Automations，跨会话记忆

- 云端（chatgpt.com/codex）：异步大任务，并行多任务，不占本地资源

加上手机端（Codex Remote）和 Chrome 扩展，基本上随时随地都能派活。

关键体验：本地和云端无缝交接。你可以在 CLI 里开始一个任务，把它交给云端继续跑，然后在手机上查看进度和审批。

七、定价与选型（2026 年 8 月口径）

Codex 不单独卖，绑 ChatGPT 套餐：

- Plus（$20/月）：有限配额，轻任务，串行执行。适合学生和偶尔用用的人。

- Pro（$200/月）：高配额、并行任务、长时任务、优先算力、Spark 实时编码。适合全职开发者。

- Team / Business / Enterprise（按席位）：团队隔离、合规日志、Automations、Slack 集成。适合研发团队。

API 侧走 Responses API 按 token 计费，支持 prompt caching（重复输入最高 90% 折扣）。

成本真相：跑一个 25 小时的长任务可能烧 1300 万 token，按 GPT-5.3-Codex 价位算几百美元一次。但相对初级工程师月薪做同样的明确定义任务，边际成本仍然低。省钱的前提是：任务边界清晰、测试可验证、人工只做 review。

八、团队引入 Codex 的 30 天路径

如果你是团队负责人，想引入 Codex，建议这样分步走：

Week 1：挑 2 个有单测的服务，写 AGENTS.md，用云端跑补单测和修 lint 这类低风险任务。

Week 2：CLI 接本地，开 auto-edit 模式，只允许改 src/ 和 test/ 目录。

Week 3：Automations 接 GitHub Issue 标签（比如 codex-triage），自动出 PR 给人 review。

Week 4：跑一次 2 小时以上的长任务（如依赖升级），用 worktree + 阶段 commit 控风险。

红线：生产分支禁止直推、敏感凭证不进沙箱、所有 Codex PR 必须过原有 CI + 人工审查。

九、总结：2026 年用 Codex 的关键认知

最后总结几个核心观点：

1. Codex 已经不是代码补全工具了

它是一个能理解项目上下文、并行处理多任务、持续在后台工作的 AI 编程智能体。从写代码到审查代码，从修 bug 到写测试，从安全审计到发布网站，基本覆盖了开发的全链路。

2. 模型选择比工具选择更重要

Sol / Terra / Luna 三档模型对应不同场景。选对了能省额度、提效率。日常 Terra，重活 Sol，轻活 Luna，实时编码用 Spark。

3. AGENTS.md 和 Skills 是效率倍增器

AGENTS.md 让 Codex 懂你的项目规范，Skills 让 Codex 复用工作流。两者结合，Codex 从每次都要教变成上来就能干。

4. 任务边界清晰是省钱的前提

Codex 最擅长边界清晰、可验证的任务。把 X 模块迁移到 Y 比优化一下代码效果好十倍。模糊的需求只会浪费 token。

如果你是新手，从这三步开始：装好 Codex、写个 AGENTS.md、学会 /plan 和 /diff。

如果你是老手，重点关注：Agent Skills 用起来、Team Config 团队配置、codex exec 接 CI/CD。

Codex 更新很快，这篇文章的信息截至 2026 年 8 月。建议定期看一下官方更新日志（developers.openai.com/codex/changelog），保持跟进。

觉得有用的话，转发给同事，让他们也别再用 2025 年的方式写代码了。

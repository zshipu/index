Meta拆分Horizon手机App游戏功能，Eclipse项目将推出独立Horizon Create

2026年8月31日
| 阅读

Meta Horizon 手机 App 代码拆解显示，游戏功能将被拆分为独立应用，内部代号 Eclipse，预计命名为 Horizon Create。这一调整发生在 Reality Labs 大规模裁员重组之后，表明 Meta 正进一步切割移动端与 Quest 头显的内容绑定。

代码拆解锁定 Eclipse 项目框架

NoridoesVR 通过逆向分析 Meta Horizon 手机 App 的代码，发现了明确的拆分迹象。代码中出现了一个名为 Eclipse 的独立项目框架，该框架专门负责处理原本集成在 Horizon App 中的游戏相关模块。拆解结果显示，游戏功能的入口、渲染逻辑和社交互动组件正被逐步抽离，形成可独立运行的代码路径。

具体而言，研究者观察到 Horizon App 当前版本中仍保留了游戏功能的调用接口，但这些接口已指向一个外部模块加载机制。这意味着 App 本身将不再直接承载完整的游戏运行环境，而是作为入口引导用户跳转到新模块。代码注释和模块依赖关系进一步证实，Eclipse 项目已具备独立的资源管理和用户会话处理能力，与主 App 的数据同步通过特定 API 完成。

这一发现并非空穴来风。NoridoesVR 此前多次通过类似方法曝光 Meta 的内部计划，准确性较高。当前拆解显示，Eclipse 框架不仅包含游戏核心，还预留了内容创作工具的扩展位，暗示 Meta 希望将游戏与创作功能打包后独立出去。整个逆向过程揭示了 Meta 工程团队已在数月前就开始为此做准备，代码结构调整痕迹清晰可见。

这些技术细节表明，Meta 并非临时起意，而是有计划地重构移动端产品架构。拆分后的代码体积预计会显著降低主 App 的安装包大小，同时为未来针对不同模块的独立更新铺路。（本节约420字）

游戏功能将独立为 Horizon Create App

根据代码中的命名信息，新独立应用的预期名称是 Horizon Create。它将从原 Horizon Worlds 的游戏功能中切割出来，成为专注内容创作与游戏体验的单独产品。

原 Horizon App 同时承载社交、浏览和游戏等多重角色，而 Horizon Create 将专注于后两项，特别是用户生成内容的创作工具和轻量级游戏玩法。切割方式是彻底的模块分离：原有 App 保留元宇宙浏览和社交发现功能，游戏及创作入口将跳转至新 App。代码显示，两者间会通过账号统一登录实现数据打通，但运行时资源完全独立。

这一定位调整意味着 Meta 试图让 Horizon Create 成为更垂直的创作平台，用户可以在里面直接制作小型游戏或互动体验，而无需依赖 Quest 头显。命名从 Horizon Worlds 转向 Horizon Create，也传递出 Meta 希望强调“创造”而非单纯“世界浏览”的意图。

目前还不清楚新 App 是否会完全取代原有游戏入口，还是作为补充存在。但从代码架构看，Meta 明显在为两者并行运行做准备，用户可能需要在两个 App 之间切换才能获得完整体验。（本节约380字）

Meta 此前已取消 Quest 平台支持计划

今年3月，Meta旗下Reality Labs VR团队经历大规模裁员和重组。当时官方一度决定停止Horizon Worlds对Quest系列VR设备的支持，这一消息迅速引发行业震动。

然而几天之后，Meta又取消了该计划，恢复了对Quest头显的Horizon Worlds支持。这一反复显示出公司在元宇宙战略上的犹豫和内部协调困难。裁员重组本身已大幅缩减了VR内容开发团队规模，资源向更核心的方向集中。

当前移动端游戏功能的拆分，正是这一系列动作的延续。Meta似乎正在系统性降低Horizon Worlds与Quest头显的强绑定关系，转而让移动端成为相对独立的入口。代码中Eclipse项目的出现，进一步印证了这种切割思路：不再强求移动App与VR设备内容完全一致，而是允许两者发展出差异化路径。

这一背景解释了为什么Meta会在此时推动App拆分。Reality Labs的组织调整直接影响了产品决策，从取消VR支持计划到移动端模块化，都是同一战略调整的不同表现形式。（本节约350字）

移动端元宇宙策略转向模块化

此次拆分清晰体现了Meta在手机端元宇宙策略从一体式App转向轻量化、模块化内容的转变。过去Meta希望通过单一Horizon App打包所有元宇宙功能，包括社交、游戏、创作和VR衔接。现在看来，这一策略正被调整为更灵活的模块组合。

模块化意味着每个功能都可以独立迭代、独立获取用户反馈。Horizon Create作为独立App，可以针对创作用户优化界面和性能，而无需顾及主App的社交 feed 逻辑。这种转向也降低了单一App的复杂度，避免因功能堆叠导致的用户体验下降。

从更广视角看，这反映出Meta对移动端元宇宙前景的重新评估。在VR硬件渗透率仍低的情况下，手机成为主要触达用户的渠道。但手机用户对重度、复杂App的接受度有限，拆分成轻量模块可能是更现实的选择。Meta可能希望通过这种方式测试哪些功能真正能留住移动用户，再决定后续资源投入方向。

这一策略转向也为其他元宇宙参与者提供了参考：一体化的宏大愿景在落地时，可能需要先拆成可独立存活的小模块。（本节约360字）

用户需跨 App 完成完整体验

拆分之后，用户将面临更高的切换成本。原本在单一Horizon App内即可完成的发现内容、参与游戏和创作作品的流程，现在需要至少在两个App之间跳转。

例如，用户可能先在主App浏览朋友动态或公开世界，然后点击游戏入口跳转到Horizon Create进行游玩。如果想基于游戏体验进行二次创作，又需要在Create App内完成，最后可能还要切回主App分享结果。这种跨App操作会增加学习成本和摩擦，尤其对非核心用户而言。

Meta显然试图通过账号统一和深层链接来缓解这一问题，但实际效果仍有待观察。代码显示存在跨App的通知和跳转机制，但是否足够流畅目前并不清楚。用户体验的潜在下降，可能导致部分移动端用户流失，特别是那些习惯一体式社交App的人。

另一方面，独立App也可能带来好处：Horizon Create可以提供更专注、无干扰的创作环境，加载速度更快，功能更新也更及时。对重度创作用户来说，这或许是值得付出的代价。但整体而言，拆分确实让完整体验变得碎片化，用户需要主动适应新的使用流程。（本节约380字）

与国内社交 App 拆分模式形成对比

Meta的这次拆分与中国主流社交和元宇宙相关App的实践形成有趣对比。国内平台如微信、抖音等，也经常将特定功能拆分成独立App或小程序，但路径和逻辑有所不同。

微信曾将支付、游戏、小程序等功能逐步模块化，但始终保持主App作为统一入口，拆分后的功能多以小程序或子应用形式存在，用户无需下载多个完整App。抖音则通过抖音火山版、抖音极速版等不同版本实现功能和用户分层，但核心社交和内容发现仍高度集成。

相比之下，Meta直接将游戏创作功能完全独立为新App，更接近于将一个产品拆成两个重量级应用。这种做法在中国市场可能面临更高阻力，因为国内用户对多App切换的容忍度相对较低。许多中国元宇宙项目如Roblox类产品或VR社交App，更倾向于保持功能集成，以降低用户门槛。

这一对比对竞争格局的启示在于：Meta如果希望在全球尤其是亚洲市场扩大移动元宇宙影响力，可能需要调整拆分力度，向更集成化的方向靠拢。否则，在用户获取和留存上会与中国竞品形成明显差距。中国App的拆分模式通常服务于流量分发和商业变现，而Meta的拆分更多源于技术架构和组织调整，两者出发点不同，最终呈现的产品形态也差异明显。（本节约410字）

发布时间与最终形态仍未确定

尽管代码拆解已明确显示Eclipse项目和Horizon Create的开发方向，但Meta尚未公布任何具体上线时间表。NoridoesVR的发现仅代表当前代码状态，最终产品形态仍可能随公司内部决策发生变化。

Reality Labs近期的多次组织调整表明，Meta的元宇宙相关计划仍处于动态调整中。Horizon Create的范围、功能列表和与主App的集成深度，都可能根据测试反馈和资源分配情况进行修改。目前还不清楚该应用是否会同步推出iOS和Android版本，以及是否会保留对Quest头显的部分适配。

这种不确定性是Meta元宇宙战略的典型特征。从最初的宏大愿景，到现实中的反复调整，再到现在的模块化拆分，公司一直在根据实际情况修正方向。用户和开发者只能等待官方进一步消息，才能判断这一独立应用最终会以何种面貌出现。

总体来看，代码层面的拆分迹象已足够清晰，但从代码到正式发布之间，仍存在较多变量。Meta下一步如何平衡移动端与VR端的关系，将直接决定Horizon Create的成败。（本节约340字）

一分钱没花，我把 Codex CLI 接上 DeepSeek，还学会了用 skill

2026年8月15日
| 阅读

最近一周，我从"只会复制粘贴代码"的 AI 小白，到把 Codex CLI 接上 DeepSeek、装上 skill、发出第一篇公众号推文。过程挺折腾，坑踩了不少，这篇把来龙去脉和配置方法都写给你。

● ● ●

开篇

上周二晚上十一点多，我照例瘫在椅子上刷 B站。首页推了一条视频：有人在终端里敲几行字，AI 自己就把项目从零搭起来了，还能配图、写文章。

我盯着屏幕看了三遍。

第一遍想的是，这玩意儿跟我有关系吗——我连命令行都只敢复制粘贴，cd 和 ls 都要现查。第二遍，评论区清一色"太香了"“省了几百块订阅费”。第三遍……我默默把视频收藏，然后去搜"Codex CLI 是什么"。

这一搜，就搜进去了一整个星期。

深夜刷 B 站看到教程的开篇场景图

一、为什么是这三件套

先交代背景，免得你没听过这些名字。

Codex CLI 是 OpenAI 出的命令行 AI 编程工具：你打字说需求，它自己读文件、写代码、跑命令、改 bug，干完还跟你汇报。理念很酷，但有个现实问题——它默认连 OpenAI 的服务。没国外订阅账号？登录都登不进去。有账号？官方额度烧得飞快，还时不时听说有人被封号。

这俩坑，随便一个都能把我劝退。

然后我刷到另一条消息：DeepSeek 的 V4-Flash 正式版在 2026 年 7 月 31 日开放公测，原生支持 Codex 用的 Responses API，还专门做了适配。价格更离谱：输入 1 元/百万 token，输出 2 元/百万 token，缓存命中只要 0.02 元。什么概念？我写一整篇长文，可能连一分钱都花不到。

但接上去不是改个地址就行。Codex 走的是 Responses API，国内大多数模型只有 Chat Completions 接口，两套协议的字段、流式格式、工具调用全不一样，硬接就是一串 404。这时候就要 cc switch 出场了——一个免费开源的桌面小工具，专门帮你切换、管理 Codex 和 Claude Code 这些工具的模型供应商，内置几十个厂商预设。

Responses API 与 Chat Completions 协议不兼容对比图

至于 skill，你可以理解成"给 AI 的说明书"：告诉它你会什么、按什么流程干活。装上合适的 skill，Codex 就不只是写代码的，还能帮你写公众号文章、配图、排版。

三件套齐了，故事才刚开始。

二、重头戏：本地路由起来了，但一直在报错

按 B 站教程走：装 cc switch → 选 DeepSeek 预设 → 填 API Key → 打开"本地路由"让它接管 Codex → 启用供应商。前几步都挺顺，cc switch 自动把配置改写成本地代理地址——就是那个 http://127.0.0.1:15721/v1（厂商密钥也藏在它自己那边，不写进 Codex 配置，这个设计我当时觉得还挺安全）。

然后噩梦来了。Codex 认了 DeepSeek，但一对话就开始报错。

先是 /responses 404。 我检查路由开关，开着啊？重开一遍，好了几分钟，又 404。

接着是模型列表刷不出来。 终端里敲 /model，空空如也。教程说重启进程就能加载，我重启了，还是空的（后来才知道它有时不吃热加载）。

再后来是请求自己跑偏。 明明启用的是 DeepSeek，结果它偷偷切回别的供应商。

那两天的状态就是：改一下 → 重启 → 又报错 → 再改 → 再重启。凌晨一点的屏幕，一半是报错日志，一半是我的黑眼圈……说实话，中途我差点放弃——我连说明书都没读完，凭什么觉得自己能搞定？

最后怎么修好的？我把网上能搜到的排查清单抄了一遍，挨个对：

  •  404

    ？看 baseURL 是不是手滑加了 /chat/completions 后缀，只填域名根地址就够。

  •  

    模型列表不加载？完全退出 Codex 进程再重进。

  •  

    请求跑偏？回 cc switch 确认启用的是不是 DeepSeek，本地路由总开关有没有被关掉。

本地路由报错排查清单示意图

三条全查完，终于通了。我在终端里敲了句"你是谁"，它回：“我是 DeepSeek-V4-Flash。” 就这一行字，我盯着看了半分钟，跟中了彩票似的。

三、装 skill，第一次感觉"这玩意能帮我干活"

跑通模型只是第一步。真正让我觉得值回票价的，是 skill。

Codex 自带一个 skill-installer，可以装社区分享的 skill；社区里也有现成仓库，一行命令整包装进来。装完它们躺在我用户目录的 .codex/skills/ 下，需要时 Codex 自动读对应说明。

我装了个写公众号推文的 skill。流程是这样：给它一个话题 → 它自己上网搜素材、列大纲 → 写初稿 → 生成手绘风格的配图 → 排版 → 直接传到我公众号的草稿箱。全程我只需要在关键节点点确认。

第一次看它跑完整条流水线，我有点恍惚。我花了一周才把环境折腾明白，它十分钟就把"想法 → 草稿箱"这条路走完了。我忽然懂了评论区那句"太香了"——工具本身不值钱，值钱的是你愿意花一周把它跑通，然后它开始替你干活。

你正在看的这篇，就是它帮忙写的。

四、写在最后：一分钱没花，但我赚到了

算账时间。这一周折腾下来，DeepSeek 那边我几乎没花钱——注册送的额度加上每百万 token 一两块的单价，我这种用量连零头都花不完。比起动辄几十上百的订阅费，这波属实是"白嫖"了。

但我赚到的不是省下的钱，是三个认知：

坑不可怕，怕的是没人告诉你坑在哪。 我踩的 404、模型列表不加载、请求跑偏，网上全有现成排查清单，只是我一开始没去查。

工具的上限，取决于你给它的"说明书"。 同样的 Codex，会配 skill 和不会配，完全是两个物种。

趁便宜赶紧用。 写这篇文章的时候，新闻已经在说 DeepSeek 计划上调 API 价格了……谁知道下次打开，还是不是这个价。

如果你也想从零把 Codex 跑起来，我的建议很简单：找个 B 站视频跟着走一遍，先别管原理，跑通了再回头看文档。遇到报错就去搜"故障排查"，比我硬扛强多了。对了，别在晚上十一点开始折腾，真的。

最后问一句：你最近有没有什么工具，是"跑通之前想放弃、跑通之后真香"的？ 评论区聊聊，让我知道我不是一个人。

结尾金句卡：跑通之前想放弃、跑通之后真香

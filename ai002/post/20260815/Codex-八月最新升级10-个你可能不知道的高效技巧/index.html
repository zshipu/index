Codex 八月最新升级：10 个你可能不知道的高效技巧

2026年8月15日
| 阅读

如果你觉得 Codex 还只是个「帮你写代码的聊天框」，那你可能错过了过去一个月最实用的一波更新。

八月刚过去十天，Codex 已经连续推了两个大版本——v0.144.6 和 v0.147.0。GPT-5.6 三档模型全面适配、后台并行运行、自动审批子代理、可移植插件……每一个都能直接改变你的工作流。

这篇文章不聊虚的，直接上干货：10 个最新、最实用的 Codex 技巧，从入门到进阶全覆盖。

一、八月更新速览：两个版本，一堆新东西

先快速过一下八月的两次重要更新，后面技巧会用到这些新功能。

v0.144.6（8月7日）：GPT-5.6 全面适配

这个版本核心就一件事：把 GPT-5.6 三个变体（Sol / Terra / Luna）的内置指令全部刷新了，同时修正了各自的上下文窗口大小。简单说就是——模型更聪明了，Codex 也更会用了。

之前可能还需要手动调模型参数，现在内置指令已经优化好了，直接用就行。

v0.147.0（8月8日）：Agent 插件 + 智能审批

这个版本信息量就大了：

- 可移植 Agent Plugins：插件可以随身带，还能搜索本地、个人、工作区、远程插件市场

- 更丰富的会话管理：命名、置顶、分支，像管理 Git 分支一样管理对话

- 更智能的审批工作流：低风险操作自动过，高风险才拦你

- MCP 2026-07-28 支持：最新的模型上下文协议

- Amazon Bedrock 缓存：用 AWS 的同学爽了

下面我们一个个拆，看看这些新功能怎么用才高效。

二、10 个你可能不知道的高效技巧

技巧 1：后台并行运行，Codex 默默干活不打扰

八月新加的杀手级功能之一。以前你让 Codex 跑个测试、改个 bug，就得盯着终端等它跑完，啥也干不了。现在不用了。

Codex 可以在后台默默运行，你继续写你的代码、查你的资料，它在旁边把活干了。等它干完了，通知你一声就行。

怎么用：在 CLI 里启动任务后，按特定快捷键就能把任务切到后台，或者直接用 codex exec 加后台参数。桌面端更简单，直接开新线程就行。

适用场景：跑测试套件、重构大文件、批量改代码、生成文档——这些耗时间但不需要你实时盯着的活。

想象一下：上班先让 Codex 把昨晚的 PR 全审一遍，你去泡杯咖啡，回来就有结果了。这才是 AI 编程助手该有的样子。

技巧 2：自动审批子代理，96% 拦截率的安全守门员

很多人不敢开 –approve-for-me，怕 Codex 乱删文件、乱装包。这个新功能完美解决了这个问题。

v0.147.0 新增了一个 auto-review 子代理——相当于给 Codex 配了个安全审核员。每次它要执行工具调用前，子代理会先按风险框架评估：

- 低风险操作（读文件、查日志、跑测试）：自动批准，不打扰你

- 中风险操作（改配置、装依赖）：可能问你一下

- 高风险操作（删文件、传数据、动凭证）：直接拒绝或者必须你手动确认

OpenAI 官方数据：96.1% 的恶意行为能拦住，同时减少 200 倍的人工干预。这个数字相当夸张了。

怎么开：CLI 加一个 –auto-approve-with-review 之类的 flag（具体命令看你版本的 codex –help）。

最适合的场景：CI/CD 流水线、夜间自动任务、你不想被频繁打断的深度工作时间。

技巧 3：Appshots——截图直接丢进对话线程

这个功能是 macOS 用户专属的福利（Windows 版本应该也快了）。

以前你想让 Codex 帮忙看一个报错窗口、一个 UI 界面、一张设计图，得先截图、保存、找到文件、拖进去……流程特别长。

现在简单了：按一个热键，直接把当前打开的应用窗口截图附加到 Codex 线程里。连文字内容都能一起识别（OCR 内置）。

怎么用：在 Codex 桌面端设置里配置 Appshots 热键，然后对着任何应用窗口按热键，截图自动进当前线程。

适用场景：

- 「这个报错什么意思？」→ 截个报错窗口

- 「帮我把这个页面改成这样」→ 截个设计稿

- 「这个配置界面怎么设置？」→ 截个设置面板

比你打字描述快十倍，而且不会有信息偏差。

技巧 4：@ 快速引用文件，不用手打路径

这个小技巧看起来不起眼，但每天能省你好多时间。

以前你想让 Codex 改某个文件，得打完整路径：帮我改一下 src/components/Header/Navbar.vue 里的导航逻辑。路径长一点就特别烦，还容易打错。

现在简单了：在 CLI 或桌面端输入框里打 @，直接弹出文件模糊搜索。按 Tab 或回车，路径自动插入。

进阶用法：

- @文件名：快速引用单个文件

- @文件夹名：引用整个文件夹的内容

- 多个 @：一次引用多个文件

配合 /mention 命令用效果更好，但直接打 @ 更省事。

技巧 5：! 快速执行 Shell 命令

又一个小而美的功能。

在 Codex 对话里，你想跑个 shell 命令但不想让 AI 插手？直接打 ! 后面跟命令就行。

比如：

- !npm test：直接跑测试，不经过 AI 思考

- !git status：快速看 git 状态

- !ls -la：列文件

为什么有用？因为有时候你就是想快速跑个命令看看结果，不需要 AI 帮你分析、解释、建议。! 就是「别废话，直接跑」。

跑完结果会显示在对话里，你可以接着让 AI 分析结果，也可以继续打命令。

技巧 6：/init 项目初始化，让 Codex 认识你的项目

很多人用 Codex 的第一个问题就是：它根本不了解我的项目结构，生成的代码风格完全不对。

/init 命令就是解决这个问题的。在项目根目录输入 /init，Codex 会自动：

- 分析项目结构和目录规范

- 识别技术栈（看 package.json、requirements.txt 等）

- 读取依赖和配置文件

- 了解代码风格和约定

然后它会生成一个项目上下文，后续所有生成都会贴合你的项目风格，而不是给你写一套「通用模板代码」。

建议：每个新项目第一次用 Codex 时先跑 /init，五分钟时间，后面省你无数次「不对，我们项目不是这么写的」。

技巧 7：Steer Mode——精确引导，别让 AI 瞎猜

你有没有过这种经历：让 Codex 改个东西，它改完了你发现理解错了，然后你说「不是这个意思」，它又改一遍，还是不对……来回三四遍，还不如自己手写。

Steer Mode 就是解决这个问题的。它的核心思路是：你说得越精确，AI 猜得越少，结果越准。

反面例子：

- 「把这个功能改好一点」——什么叫「好一点」？AI 只能猜

- 「优化一下性能」——优化哪方面？速度？内存？

正面例子：

- 「把缓存从数组改成 Map 结构，用 key 查找，时间复杂度从 O(n) 降到 O(1)」

- 「把这个按钮的点击区域扩大到 44x44pt，符合 iOS HIG 规范」

在 Steer Mode 下，你可以用更精确的指令引导 Codex，它会严格按照你的指示来，而不是自己发挥。

经验法则：如果你发现 Codex 连续两次都理解错了你的意思，别再让它猜了，把你的要求拆得更细、更具体。

技巧 8：会话分支与命名，像 Git 一样管理对话

v0.147.0 新加的功能，特别实用。

以前你用 Codex 调试一个 bug，聊着聊着想试试另一个思路，怎么办？要么新开一个会话（上下文全丢了），要么继续在原来的聊（思路混在一起）。

现在有了会话分支：直接从当前对话分叉出一个新分支，试错完了可以回来，也可以合并。就像 Git 的 branch 一样。

还有会话命名和置顶：重要的会话可以置顶，给它起个名字（比如「支付模块重构」「登录 bug 调试」），下次找的时候不用翻历史记录。

推荐工作流：

- 每个大任务开一个主会话，命名好

- 不确定的思路就分叉试，试完删掉或者合并

- 常用的配置会话置顶，随时能调出来

用习惯了之后，你会发现 Codex 不再是「一次性聊天框」，而是一个真正的项目工作台。

技巧 9：可移植 Agent Plugins，插件随身带

以前 Codex 的插件只能装在本地，换台电脑就得重装。现在不一样了。

v0.147.0 推出了可移植 Agent Plugins，插件可以打包带走，还支持多个层级的插件市场：

- 本地插件：当前项目专用

- 个人插件：你所有项目都能用

- 工作区插件：团队共享

- 远程插件市场：社区分享的

而且可以跨目录搜索，找插件特别方便。

最实用的场景：你团队有一套内部开发规范，做成一个 Plugin，所有人装上之后，Codex 生成的代码自动符合团队规范，不用每次都强调。

安装方式也很简单：codex plugin marketplace add 插件名，或者从 GitHub 仓库直接装。

技巧 10：Subagents 并行干活，但别乱用

Codex 可以派生子代理（Subagents）并行干活，听起来很厉害——一个变十个，效率翻十倍？

没那么简单。Subagents 不是魔法，它们是有独立上下文的并行工作者，每个都要消耗 token。用对了事半功倍，用错了浪费钱还添乱。

正确用法：每个子代理负责一个独立、清晰的任务，它们之间不需要交流。

比如：

- 派三个代理：一个审安全、一个审测试覆盖、一个查数据模型。它们都只看文件不修改，最后把结果汇总给你。

- 派两个代理：一个写前端组件、一个写后端接口。约定好接口格式，各干各的。

错误用法：「派几个代理帮我搞定这个问题」——任务不明确，子代理不知道干啥，最后各干各的，结果一团糟。

原则：子代理的任务越具体、越独立，效果越好。如果任务需要紧密协作，别拆，让一个代理从头到尾做。

三、Agent Skills 进阶：让 Codex 变成「专业选手」

如果你还只用 Codex 的默认能力，那你只用到了它的一半。

Agent Skills 是 Codex 的「专业技能包」——装上之后，Codex 就从「通用编程助手」变成了「某领域专家」。

怎么装 Skills

最简单的方式是用 skills CLI：

- 从 GitHub 装：npx skills add 仓库名/skill名

- 装特定的：npx skills add vercel-labs/agent-skills

- 列已装的：npx skills list

Codex 原生也支持 Plugin 格式，有些 Skill 提供了 .codex-plugin/plugin.json，可以直接当 Codex Plugin 装，体验更好。

推荐必装的几个 Skills

- caveman：代码优化和重构专家，专治烂代码

- release-check：发布前检查清单，版本号、changelog、测试、迁移全查一遍

- expo/skills：Expo 官方移动端技能包，做 React Native 的必装

- agent-skills：通用技能集合，包含很多实用小工具

自己写 Skill 也不难

如果你有一些重复性的工作流，可以自己写一个 Skill。结构很简单：

- SKILL.md：核心文件，告诉 Codex 什么时候调用、怎么调用

- scripts/：你的脚本（Python、Shell 都行）

- references/：参考文档

- assets/：模板或资源

比如你团队有一套代码审查规范，写成一个 Skill，Codex 审 PR 的时候自动按你们的标准来，比每次口头说靠谱多了。

四、学生福利：Codex for Students

八月还有个好消息：Codex for Students 上线了。

美国和加拿大的在校大学生，验证学生身份后，可以领 100 美元 ChatGPT 额度或者 2500 点 Codex 积分。

对于学生党来说，这相当于免费体验 Pro 级别的功能。写作业、做项目、学编程，有 Codex 帮忙效率高很多。

国内的同学虽然暂时不能直接领，但可以关注一下，说不定以后会扩展到更多地区。

五、总结：八月更新的核心价值

最后总结一下，八月这波更新，本质上是在做三件事：

第一，更省心。后台运行、自动审批、Appshots——这些功能都是为了减少你和 Codex 的交互成本，让它更像一个「默默干活的助手」，而不是一个需要你不停盯着的聊天框。

第二，更专业。Agent Plugins、Skills、会话分支——这些功能让 Codex 从「通用工具」变成「可以定制的专业工作台」。你可以根据自己的工作流来配置它，而不是迁就它的默认设置。

第三，更安全。自动审批子代理、权限管控、风险分级——AI 编程助手的安全问题一直是大家最担心的，OpenAI 也在认真解决。96% 的拦截率虽然不是 100%，但已经比很多人手动审核靠谱了。

如果你之前用过 Codex 但觉得「也就那样」，建议再试一次。过去几个月它的进化速度真的很快，可能已经不是你印象中的那个 Codex 了。

毕竟，AI 编程这个赛道，每个月都在变天。

Codex CLI命令大全：效率提升必备

2026年8月15日
| 阅读

点击上方“全栈程序员社区”，星标公众号

重磅干货，第一时间送达

很多程序员装好 Codex CLI 后，只会输入 codex，然后把它当成终端里的聊天框。其实真正拉开效率差距的，是会话续接、目录控制、非交互执行和代码审查这些稳定能力。

🚀 安装与状态检查

官方快速安装可以使用：

<span leaf="">npm install -g @openai/codex</span><span leaf=""><br></span><span leaf="">codex login</span><span leaf=""><br></span><span leaf="">codex login status</span><span leaf=""><br></span><span leaf="">codex update</span>

codex login 会引导完成登录，codex login status 适合在自动化脚本里确认认证状态。安装版本支持自更新时，codex update 可以检查并应用更新。

🧭 从正确目录启动

直接运行 codex 会进入交互界面。你也可以用 -C 指定项目目录，减少先切目录再启动的步骤：

<span leaf="">codex -C ./service-a</span>

需要带着截图或报错图开始分析，可以用 -i 附加图片：

<span leaf="">codex -C ./service-a -i ./error.png&nbsp;</span><span><span leaf="">"定位异常链路并给出验证计划"</span></span>

目录要尽量小而准确。把工具放进整个工作盘，既增加无关上下文，也容易扩大修改范围。

🔁 续接与分叉

中断后继续最近一次交互任务，可以使用：

<span leaf="">codex resume --last</span>

如果想保留原会话，再从同一上下文试另一条方案，可以用：

<span leaf="">codex fork --last</span>

一个适合继续未完工作，一个适合做安全对照。重构、依赖升级和性能优化尤其适合先分叉，避免新尝试污染原思路。

🤖 非交互执行

脚本或 CI 场景可使用稳定的 codex exec：

<span leaf="">codex&nbsp;</span><span><span leaf="">exec</span></span><span><span leaf="">"运行测试并总结失败原因，不修改代码"</span></span>

想继续最近一次非交互任务，可用 codex exec resume --last。自动化里一定要写清允许修改的范围、必须执行的测试和输出格式，别只写一句“帮我修好”。

🔍 审查比生成更值得常用

codex review 可以检查未提交变更、分支差异或指定提交。把它放在提交前，比出问题后再让 AI 猜原因省心得多。日常还可用 codex doctor 生成本地环境诊断，排查安装、配置、认证、Git 与运行时问题。

命令写对只是第一步，提示也要可执行。比如把“优化这个项目”改成“先定位启动最慢的三个环节，只给分析与测量方案，不改业务代码”，输出会更稳定。修复任务则应写明复现方式、允许修改的目录、必须通过的测试，以及不能改变的外部行为。

真正高效的组合不是记住几十条命令，而是固定一套流程：进入正确目录，先计划，再修改，运行测试，最后审查差异。权限也要从小到大开放，工作区写入通常够用，不要为了省一次确认就长期绕过安全边界。

程序员AI工具 的价值，最终体现在可复现、可检查、可交付。命令只是入口，工程习惯才是放大器。

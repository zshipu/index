Codex CLI实用命令分享：提升效率

2026年8月15日
| 阅读

点击上方“全栈程序员社区”，星标公众号

重磅干货，第一时间送达

很多人装好 Codex CLI 后，只会输入 codex 打开终端界面。其实官方命令已经覆盖交互开发、自动化、代码审查、会话续接和工具接入。把下面几组用熟，效率会明显提升。

直接进入项目：codex

在仓库目录运行 codex，适合边沟通边查看变更。你也可以在命令后直接加任务说明，让会话带着目标启动。

需要临时切换工作目录时，可以使用 codex -C 路径。它比先手动跳转目录更适合脚本化场景。

自动执行任务：codex exec

codex exec 适合不需要持续交互的任务，例如整理测试失败、生成变更摘要、分析一组日志。提示词可以直接放在命令后，也能从标准输入传入。

在 CI 或批处理里，建议明确输出要求、允许修改的范围和验收命令。

接着上次做：codex resume

复杂任务经常跨多个时段。codex resume --last 可以续接当前目录最近的交互会话，减少上下文断层。

非交互任务也有对应的续接方式：codex exec resume --last。它适合某次自动执行完成了一半，后续还要继续收尾的情况。

把审查独立出来：codex review

提交前可以运行 codex review --uncommitted 查看未提交变更，也可以用 --base 对比分支，或用 --commit 审查指定提交。代码生成和代码审查分成两步，往往比一次性“写完顺便看看”更可靠。

管理外部工具：codex mcp

需要接入 MCP 服务时，先用 codex mcp list 查看配置，再按需添加或移除。不要为了显得强大就堆很多服务，连接越多，权限边界和故障来源也越多。

三个容易忽略的小命令

codex completion zsh 可以生成命令补全；codex doctor 用于整理安装、配置、认证、运行环境等诊断信息；codex --help 则永远是确认当前版本能力的可靠入口。

提升效率，不是背下所有参数，而是形成节奏：交互探索用 codex，无人值守用 codex exec，中断后用 resume，提交前用 review。先把这条主线跑顺，再扩展自动化。

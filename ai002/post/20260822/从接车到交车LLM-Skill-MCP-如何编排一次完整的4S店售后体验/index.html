从接车到交车：LLM + Skill + MCP 如何编排一次完整的4S店售后体验

2026年8月22日
| 阅读

你在4S店经历过最“共情”或最“糟心”的一次售后服务是什么？评论区分享你的故事，下期我拆解里面的技术痛点！

一个奥迪Q5车主从“刹车异响”到“放心离店”背后的Agent工作流

一、开篇：当服务顾问遇上AI

场景还原

上午9:15，一辆奥迪Q5驶入售后接待区。客户张先生下车后对我说：“师傅，最近低速刹车的时候有尖锐异响，特别是倒车的时候更明显。我马上要跑一趟长途，有点担心安全问题。”

作为一个干过5年豪华品牌服务顾问的Java架构师，我太熟悉这个场景了。这句话背后藏着多少信息——客户的真实焦虑、车辆的潜在隐患、服务流程的启动信号、还有后续一连串工单、诊断、维修、质检、交车的链条。

今天这篇文章，我用Agent技术栈来拆解这个链条：

LLM（大语言模型） → 听懂客户没说出来的话Skill（技能） → 调用各个系统的原子能力MCP（模型上下文协议） → 让这些系统能“说同一种语言”  

这不是概念堆砌，而是一套完整的编排工作流（Orchestration Workflow）。下面我结合真实售后流程，逐段拆解。

三、逐站拆解：Agent技术如何嵌入每个售后节点

站点①：接车倾听 —— LLM的“意图识别 + 情感计算”

售后真实场景

张先生站车前，我拿接车单开始记录。他嘴上说“刹车异响”，但语速偏快，反复问“跑长途安全吗”，手一直在敲引擎盖。这是一个焦虑型客户——他真正关心的是“我的车会不会在高速上出问题”。

Agent技术映射

售后能力 Agent技术 说明
听懂故障描述 LLM意图识别 从自然语言中提取：故障现象（刹车异响）、触发条件（低速/倒车）、紧急程度（长途出行）
感知客户情绪 LLM情感分析 焦虑指数、信任度、决策风格（理性型/感性型/技术型）
生成接车话术 LLM生成回复 共情回应 + 专业安抚 + 下一步行动引导

站点②：历史查询 —— Skill + MCP 的“数据编织”

售后真实场景

我一边安抚张先生，一边快速调出这辆Q5的维保档案。2022款，行驶4.2万公里，去年8月做过一次刹车片更换，但当时用的是副厂件。这条信息足以改变整个维修策略——如果当时用的是原厂件，刹车异响大概率是正常磨损；但副厂件意味着可能出现了偏磨或材质问题。

别再把 Codex 当聊天机器人：从安装到真正干活，一篇讲透

2026年8月16日
| 阅读

2026 最新实操指南

桌面端、IDE、CLI、云端怎么选？提示词怎么写？权限怎么开才安全？

如果你看过半年前的 Codex 教程，大概率已经过时了。现在的 Codex 不只是一个命令行工具，而是一套覆盖桌面应用、代码编辑器、终端和云端任务的编码智能体。真正的问题已经不是“它会不会写代码”，而是“你怎样让它稳定地完成一件事”。

这篇文章不堆功能名词，直接解决三个问题：

  1. 新手应该从哪个入口开始；

  2. 怎样给 Codex 一个能落地、能验收的任务；

  3. 怎样避免它改错文件、误跑命令，或者交出一份“看起来完成了”的半成品。

一、先认清今天的 Codex：它已经不是代码补全

传统代码补全是在你敲下一行时猜下一行。Codex 的工作单位更大：它可以读取仓库、搜索文件、修改代码、运行命令、执行测试、检查 diff，再把结果交给你审阅。

你可以把它理解成一个“受权限约束的虚拟开发者”。你给目标，它在指定项目里工作；遇到越界操作，再向你申请许可。

**我的建议很直接：**不熟悉终端，就从桌面应用或 IDE 扩展开始；日常开发高度依赖终端，再选 CLI。不要因为网上教程最多，就默认 CLI 一定最适合你。

时效提醒

截至 2026 年 8 月 7 日，官方更新日志中的最新 Codex CLI 为 0.147.0。近期版本已经加入便携式 Agent Plugins、会话分区、外部 skills 与会话导入、新版 MCP 协议支持和更严格的安全控制。旧文章里的参数可能已经废弃，例如 codex exec –full-auto 已被移除，不能再照抄。

二、最快上手：先完成一次“小闭环”

路线 A：桌面应用或 IDE 扩展

安装后，用 ChatGPT 账号或 API Key 登录，打开一个项目文件夹。第一次不要让它“重构整个项目”，先给一个可控任务：

先不要修改任何文件。阅读这个项目，告诉我： 1. 项目解决什么问题； 2. 如何启动、测试和构建； 3. 主要目录分别负责什么； 4. 你认为最值得先修的一个小问题。 最后列出你实际阅读过的文件。

这一步看似保守，却能马上检查三件事：项目目录有没有选错、Codex 能不能读到关键文件、它是否真的理解仓库。

路线 B：Codex CLI

macOS 或 Linux 当前推荐使用官方独立安装脚本：

curl -fsSL https://chatgpt.com/codex/install.sh | sh

Windows 可在 PowerShell 中使用官方安装脚本：

powershell -ExecutionPolicy ByPass -c “irm https://chatgpt.com/codex/install.ps1 | iex”

安装后，进入项目目录运行：

codex

首次运行会要求登录。普通个人使用，优先选择 ChatGPT 登录；CI、共享自动化或按 API 用量结算时，再考虑 API Key。API Key 登录不包含部分云端功能与集成。

三、提示词别写成愿望，要写成验收单

很多人第一次用 Codex，会输入一句：“帮我优化这个项目。”这不是任务，只是愿望。所谓优化，到底是速度、架构、界面，还是测试覆盖率？Codex只能自己猜。

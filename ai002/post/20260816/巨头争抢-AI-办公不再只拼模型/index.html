巨头争抢 AI 办公，不再只拼模型

2026年8月16日
| 阅读

Agent 正在重新定义，一家公司究竟应该怎样工作。

文丨****陈然

过去半年，Agent 最先改变的是程序员的工作方式。

程序员把越来越复杂的任务交给 AI，让它理解代码库、修改文件、运行程序、检查结果，再根据反馈继续完成后续工作。Claude Code 的快速增长证明了一件事，用户愿意为 AI 真正替自己完成工作付费。

现在，这件事正在走出程序员的电脑。

写文档、做表格、整理会议、查找资料、处理审批，过去需要人在多个软件之间来回操作的工作，开始可以交给 Agent。

这也是为什么今年国内外巨头几乎同时把 Agent 推进办公室。

腾讯的 WorkBuddy 率先发力，阿里加速整合千问办公，字节继续强化豆包和飞书融合。海外的微软、谷歌、Anthropic 和 OpenAI 也在把 Agent 塞进文档、会议、邮件和任务执行。

一个新的市场正在形成。

三十多年前，个人电脑进入办公室之后，人们需要找到它真正能解决的问题，世界首款电子表格 VisiCalc 给出了第一个答案。今天，企业面对的问题变成了：AI 能不能真正进入生产体系，带来新的效率和价值？

办公 Agent 正在给出答案。

办公正在成为下一个 Agent 主战场

2026 年 5 月 5 日，微软发布了一年一度的《工作趋势指数年度报告》，其中的一个关键判断是：未来打开办公软件，人们看到的可能不再是一排文档和聊天窗口，而是一群可以代为工作的 AI。你交代一件事，它会自己查资料、写文档、发邮件，完成后再把结果交给你。

这个变化看起来突然，但放进过去三十多年办公生产力的变迁历程中，却可以看到一条清晰的轨迹。

第一代办公软件解决的是个人效率。1990 年前后，Word、Excel 和 PowerPoint 被装进同一个 Office 套件，写作、计算和制作图表从纸上搬进电脑。工作围绕文件展开，软件帮助每个人更快完成一份文档、一张表格或者一套幻灯片。

随着企业里的人越来越多，新的问题出现了。文件、版本和信息不断增加，几个人一起工作时，邮件附件很快变成了新的负担：哪一份是最新版，谁改了什么，接下来又该交给谁。

于是，办公软件开始把重点转向团队协作。Slack 的出现瞄准的就是这个问题。2014 年，这家公司把办公软件的重心转向沟通协作，试图用即时通讯取代电子邮件。

2020 年疫情进一步推动了这套工作方式，微软 Teams 一年内用户从 2000 万增长到 1.45 亿。中国的协同办公市场也迅速成熟，钉钉、飞书、企业微信逐渐成为企业日常工作的基础设施。

但这一阶段有一个前提：活最终还是由人来干。

人需要讨论、分工、催进度和统一口径，所以很多工作从一条消息、一次会议或者一个群聊开始。

Agent 改变的，恰恰是这个前提。

当 Agent 可以直接生成方案、拆解任务、完成初步执行后，工作的起点也开始变化。

人们可以先让 AI 快速生产出若干方案和结果，再围绕结果进行评审。讨论的内容从我们打算怎么干，逐渐变成这版做得行不行、哪里需要修改。

一位头部互联网的 AI 办公 Agent 产品负责人告诉我们：下一代的入口是任务本身。

如果这个判断成立，群聊、文件和应用都会退到后台。用户面对的中心界面，会变成一件件正在推进的任务。AI 正在做什么、做到哪一步、哪些环节需要人来决定。

研究机构 Gartner 预测，到 2028 年，三分之一的用户操作将交给 AI，由它代替人在不同软件之间完成操作。因此对行业里的玩家们来说，下一阶段比拼的重点，将从提供的工具数量转向任务完成能力。

办公软件，重新变成生产力工具

今天，腾讯、阿里、字节几乎同时加码办公 Agent，背后有一个共同判断，办公正在成为 Agent 最重要的生产力市场之一。

这个市场的想象空间远大于今天已经出现的几个办公产品。

中国有数以千万计的知识工作者，每天处理大量重复、流程化的信息任务。查资料、写报告、整理会议、制作 PPT、处理表格、跟进客户、提交审批，这些事情分散在不同软件里，占据了大量工作时间。

过去，办公软件帮助人把这些事情做得更快。Agent 开始接手其中的一部分工作。

这也是腾讯、阿里、字节的优势所在。它们本身就在企业工作的基础设施里：微信、企业微信、钉钉、飞书，以及文档、会议、邮箱、审批和知识库。

一个刚刚被真正发掘的市场，正在成为大厂共同争夺的新入口。

AI 行业的钱和算力流向，已经在印证这一趋势。

2023 年 ChatGPT 带起的那一波热潮里，人们对 AI 的想象基本等同于对话。而现在这类产品的新鲜感明显消退，期待也在变化，人们期待着 AI 能真正帮助自己完成工作。

编程是第一步。2025 年 5 月，Anthropic 的编程工具 Claude Code 正式开放使用，程序员交代需求，AI 自己读代码、改代码、跑测试。这个产品六个月做到 10 亿美元年化收入，2026 年 2 月做到 25 亿美元。在企业软件历史上，没有产品用这么短的时间走完这段路。

Claude Code 的增长很快改变了市场对 Agent 的预期。据路透社报道，Anthropic 的年化收入在一年多时间里从约 10 亿美元增长到 300 亿美元以上，其中七成以上来自 API 和企业合同。

今年开始，同样的方法被搬进了办公场景。写周报、整理数据、做 PPT，这些活的结构和写代码类似，目标明确，步骤可拆解，结果可以被检查与修订。2026 年初开始，微软、谷歌和一批创业公司密集把 Agent 装进办公产品，这个原本属于程序员圈子的概念，开始被普通上班族接触到。

算力的账单记录了这一切。谷歌 CEO Sundar Pichai 在今年 5 月的开发者大会上给过一组数——两年前，谷歌全部产品每月处理 9.7 万亿 token；去年涨到 480 万亿，今年是 3200 万亿，一年翻了 7 倍。

中国的曲线更陡。国家数据局今年 3 月公布，中国日均 token 调用量已超过 140 万亿，两年前是 1000 亿；仅 2026 年头三个月就比去年底又涨了四成多。国家数据局局长刘烈宏对此的归因是，应用在从能对话，走向能决策执行的 Agent。在开发者调用各家模型的中转平台 OpenRouter 上，今年 2 月中国模型的周调用量首次超过美国模型，此后连续数周领先。

就像三十多年前个人电脑把工作搬进数字世界，十多年前云与协作软件又重新组织了人与人之间的协作，随着人们开始把越来越多、越来越复杂的工作交给 AI，办公软件也将再次被重新定义。

模型很重要，但并非决定胜负的关键

2026 年，一位券商研究员的早晨从一句话开始。他对屏幕上的 Agent 说：把这家公司近三年的毛利率和同行对一遍，标出异常季度，给出核心结论。几分钟后，一份带出处的报告出现在桌面上。行情软件还开着，但他已经很久没有亲手翻过财报了。

这样的早晨正在变多。今年 5 月 26 日，美国人口普查局调查了约 120 万家企业，19.5% 的美国企业已经在生产经营中使用 AI，信息业接近四成，金融保险业超过三分之一。企业用 AI 的方式也在变。过去主要用它查资料、写文字、回答问题，现在开始把更复杂的工作交给 Agent。

但对企业来说，一个新的问题也随之出现。市面上的 Agent 越来越多，究竟该选哪一个？

一个真正能干活的 Agent，大致由三层能力构成。

模型负责理解和推理，Harness 负责调用工具、管理上下文和执行任务，上下文则来自文件、数据、历史记录以及企业内部的知识和规则。

前两层决定 Agent 能不能把事情做成，最后一层决定它究竟能把事情做到什么程度。

过去行业最关注前两层。模型越聪明，Harness 越成熟，Agent 看起来就越强。但办公场景正在出现一个变化，头部模型的基础能力越来越接近，成熟 Harness 的执行方式也在快速趋同。

腾讯在 2026 年 7 月曾开源了一套评测集 WorkBuddy Bench。它将七个头部模型，分别装进了 CodeBuddy Code 和 Claude Code 两套 harness 中，让它们完成 260 项任务。这些任务分为代码、网页、办公和安全四类，其中办公 50 项，涉及数据和表格处理、文档与演示材料、对账和后台运营、工作空间自动化以及合规材料整理。

其中最关键的结论是，在日常办公场景里，头部模型之间的能力已经相当接近。

在 CodeBuddy Code 环境下，七个模型的办公得分集中在 77.47 分至 82.37 分之间，最高和最低相差不到 5 分，混元与 Claude Opus 的差距只有 0.29 分。没有哪个模型在办公任务上形成明显领先。

换一套 Harness，结果也没有发生太大变化。在 Claude Code 的环境下，七个模型中有五个得分变化不到 2 分，中位变化只有 0.86 分。这意味着，在日常办公任务中，只要使用的是相对成熟的执行框架，Harness 本身带来的差异也有限。

Claude Code 此前一直被视为拥有目前最成熟的 harness，但实际上，它的核心逻辑其实并不复杂。一位头部 AI Agent 产品负责人告诉《晚点 LatePost》，上下文怎么编排、工具怎么调用、记忆怎么管理，说到底都是工程问题。“工程做到精细之后，各家的方案会越长越像，藏不住多少秘密。”OpenAI 甚至把 Codex 的 harness 开源了。

代码和安全任务是例外。在这些场景中，模型与 harness 的搭配会明显影响结果。以安全任务为例，同一个模型更换 harness 后，得分平均相差 8.6 分，排名也会发生较大变化。

这个结果未必意味着模型能力已经没有差异，但至少说明，在大量标准化的办公任务里，模型已经越来越难凭借单项能力拉开足够大的差距。

两年前，AI 行业普遍相信，模型领先，产品自然也会领先。如今这种关系正在松动。

因此，当市场上同时存在多个足够好、又能快速替换的模型时，Agent 产品不再需要与某一个模型深度绑定。

WorkBuddy 就采用了多模型架构。用户既可以使用腾讯自己的混元，也可以接入 GLM、Kimi、MiniMax、DeepSeek 等外部模型。

对产品来说，模型因此变成了一项可以动态调度的能力，不同任务调用不同模型，新模型出现后也可以继续接入。

办公 Agent 的竞争变量因此开始发生变化。模型迭代越快，上层 Agent 能够调用的能力就越丰富。

模型依然决定能力上限，却越来越难单独决定产品最终能走多远。

安全和开放是企业选配的重要标尺

究竟是什么决定一款办公 Agent 能不能进入企业？

WorkBuddy 是一个很好的观察样本。

作为目前国内用户规模领先的办公 Agent 产品，它开始进入更多企业工作场景。到了企业里，Agent 面对的考题完全不同。

ROI 当然重要。能不能解决问题、提高效率、真正产生收益，是企业愿意使用 Agent 的前提。

但当 Agent 开始接触企业真实的数据、权限和业务系统，安全可控和开放友好，正在成为衡量一款 Agent 能不能真正落地的重要标准。

先说安全。

对中国企业来说，海外 Agent 还多了一层现实问题：服务可用性。

OpenAI 和 Anthropic 目前都没有正式向中国大陆提供服务。对个人用户来说，偶尔无法访问或者换一个账号，影响尚且有限。一家企业一旦把日常工作流接入 Agent，服务稳定性就会变成真正的采购问题。

数据也一样。对企业来说，问题很现实，数据放在哪里，谁可以访问，出了问题谁负责，Agent 能做到哪一步。

Agent 真正开始替人办公以后，风险还会继续增加。它不再只是读取资料和生成答案，也可能删除文件、修改数据、发送邮件或者调用内部系统。企业因此需要知道哪些操作可以撤销，哪些权限必须人工确认，Agent 可以自主行动到什么范围。

WorkBuddy 为此设计了分层权限规则，可以对操作设置允许、询问和拒绝；用户也可以指定工作目录，限制 Agent 能够读写的文件范围。企业版还提供隔离部署和离线部署等不同方式。

2026 年 6 月，广东省级政务智能中枢湾擎上线试运行，并预发布湾擎版 WorkBuddy。湾擎本身设置了 Token 级安全防护和分区运行的 AI 创新沙箱，WorkBuddy 随后计划在广东省直单位开展试点。政务、金融、医疗等行业的采用，会让安全从产品参数变成采购门槛。Agent 能不能进入企业，首先取决于企业敢不敢让它接触真实数据和真实权限。

安全解决的是企业敢不敢用，开放则解决的是企业能不能可持续的用。

企业不会希望每一次模型升级、工具变化，都重新部署一套办公系统。

WorkBuddy 企业版允许管理员配置不同模型，也支持自定义模型；工具层支持 MCP，企业可以把 CRM、数据库和其他业务系统接进来；技能层则允许企业继续使用自己的 Skill。腾讯在 8 月 12 日发布的二季度财报里，也把 WorkBuddy 的多模型选择和 Skills 生态列为其市场表现的重要支撑。

腾讯会议甚至同时开放给 WorkBuddy、Claude Code、Codex 等不同 Agent 使用。

对企业来说，这意味着底层模型、工具和 Agent 本身都可以变化，原有的工作环境仍然能够继续使用。

阿里也在沿着类似的方向开放。钉钉允许企业接入自有模型和自定义 MCP，OpenClaw 这样的第三方 Agent 也可以通过钉钉 MCP 操作日程、AI 表格等服务。

办公 Agent 最终可能会越来越像企业的一层智能基础设施，而不是一个需要企业重新迁移全部工作的封闭软件。

真正的壁垒，是企业的工作上下文

安全和开放，解决了 Agent 能不能进入企业的问题。

真正的竞争，从它进入企业的那一天才开始。它每天接触文件、会议、项目、客户和审批，逐渐知道这家公司过去发生过什么、谁负责什么、什么事情需要谁决定。

这就是上下文。

一家公司多年积累的文件、会议记录、客户往来、人员关系、审批规则和历史决策，不可能随着换一个 Agent 重新建立起来。模型可以购买，工具可以接入，企业真正的工作上下文却需要时间积累。

举个例子，一名销售刚刚结束和客户的会议。第一层 Agent 可以总结会议纪要；再进一步，它可以读取客户过去的邮件，整理客户需求，生成跟进邮件。真正进入工作流以后，事情会复杂很多。

客户把预算从 100 万压到 80 万，Agent 需要知道这个项目之前报过几轮价格，客户提出了哪些新需求，原方案需要改什么，价格变化是否超过销售权限，谁需要审批，以及下一次应该什么时候跟进。

理想状态下，它可以自动找到历史报价，修改方案；如果折扣超过权限，发起审批；审批通过后生成新的报价单，再把跟进时间写进日程。

这时候，Agent 才真正开始接手一项工作。

法务也是如此。生成合同、指出风险条款只是最基础的任务。真正进入工作流以后，Agent 需要知道公司历史上使用过什么合同版本，哪些修改超出授权范围，以及不同风险应该交给谁审批。

办公还有一个天然属性，多人协作。

人员分工、审批权限和沟通关系，本身就是完成任务的一部分。销售知道折扣超过多少需要找主管，财务知道哪类支出需要谁审批，法务知道哪些合同修改必须升级处理。过去这些规则散落在制度、软件和人的经验里，Agent 要真正接手工作，就得逐渐理解这层关系网。

这种积累会越来越明显。Agent 用得越久，接触到的项目、文件、会议和决策越多，对企业的理解就越深；理解越深，它能够接手的任务也就越复杂。

到最后，企业依赖的不只是一个 Agent，而是一套围绕 Agent 积累起来的工作上下文。这才是办公 Agent 最难复制的部分。

这也是 WorkBuddy 值得观察的地方。

腾讯已经拥有文档、会议、企业微信、邮箱、知识库等大量企业工作基础设施。WorkBuddy 可以沿用这些已有的账号、组织架构和权限关系，让 Agent 从进入企业的第一天起，就拥有一部分真实的工作上下文。

这些能力单独看都不新鲜。真正重要的是，它们能不能最终围绕一件具体的任务连接起来。

这给了 WorkBuddy 一个天然起点。但起点最终能不能变成壁垒，仍然取决于它能不能让这些分散的数据、权限和工具真正围绕任务连接起来。

2025 年，Agent 首先在编程场景证明了自己能够完成复杂任务。2026 年，这种能力开始走向办公室。

下一阶段真正值得观察的，是 Agent 能接手多少工作，以及企业会不会因此重新组织自己的工作方式。

过去几十年的办公软件，一直在帮助人更快地写、算、沟通和协作。Agent 出现以后，一个新的问题摆在企业面前：如果一部分工作可以直接交给机器完成，人和软件之间的关系会变成什么样？

这可能才是办公 Agent 这场竞争真正重要的地方。AI 办公争夺的最终也不只是一个新的软件入口。它在重新定义，一家公司究竟应该怎样工作。

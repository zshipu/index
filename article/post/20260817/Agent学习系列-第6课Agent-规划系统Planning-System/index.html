Agent学习系列 第6课：Agent 规划系统（Planning System）

创建时间: 17/08/2026
阅读:

前面我们解决了 Agent 的"记忆"和"状态"，让它记得住、稳得住。但还有一个更根本的问题没解决——

遇到复杂任务，Agent 该先想清楚，还是先动手？

答案是显而易见的：先想清楚。一个没有规划的 Agent，面对"安排一次三天两城出差"这种任务，会想到哪做到哪，反复试错、反复踩坑，最后 token 烧了一大把还没结果。

第 6 课，我们讲 Agent 的规划系统 Planning System——让 Agent 学会"先规划，再执行"。

一、为什么需要规划

没有规划的 Agent，本质是在碰运气。它把整个任务当成一个黑盒，每次行动都凭当下感觉，而不是全局策略。

  • 随机试错

    ：同一类错误反复踩，不吸取教训。

  • 越长越乱

    ：任务步骤一多，上下文被无关信息淹没，越跑越偏。

  • 成本高

    ：大量无效的工具调用，token 烧得快，结果还不一定对。

一句话：没有规划，Agent 只是在"碰运气"；有规划，才是在"做工程"。

二、任务拆解：复杂任务 → DAG

规划的第一步，是把一个庞大含糊的任务，拆成可执行、可依赖、可并行的小步骤。最经典的载体就是 DAG（有向无环图）。

  • 可执行

    ：每个子任务都能对应到具体动作或工具调用，不再是一个空泛的目标。

  • 有依赖

    ：子任务之间有先后，比如"订机票"必须在"订酒店"前想清楚日期。

  • 可并行

    ：没有依赖关系的子任务可以同时推进，长任务提速明显。

拆得越细，Agent 越不容易跑飞；DAG 让依赖顺序一目了然，谁先谁后不会乱。

三、Plan-and-Execute：两阶段

把"想"和"做"分开，是让复杂任务稳定的关键设计。它分两个阶段：

| 角色

|

负责什么

|

不做什么
规划者 Planner

看全局、定方案，输出完整计划

|

不亲自调工具、不动手

| | 执行者 Executor |

按计划一步步调工具、拿结果

|

不擅自改方向、不临时发挥

|

规划者盯着方向和正确性，执行者盯着落地和效率。想的人不被琐事打断，做的人不被方向带偏——复杂任务才稳。

四、Tree of Thoughts：多路径推理

很多任务不是只有一条路。Tree of Thoughts（思维树）让 Agent 同时探索多条思路，而不是一头撞死在南墙上。

  • 分支

    ：面对一个问题，先发散出几个不同的解决思路。

  • 展开

    ：每条思路再往下推几步，看哪条更靠谱。

  • 收敛

    ：最后从所有叶子节点里，挑出最有希望的那条走下去。

它不走独木桥，而是广撒网、精收口——适合那些"解法不唯一、容易卡死"的开放任务。

五、Beam Search 推理

多路径虽好，但全展开太贵。Beam Search 是个折中：每一步只保留 Top-K 个最有希望的方案，其余全部剪掉。

  • 不全穷举

    ：避免组合爆炸，控制 token 成本。

  • 不只留 1 条

    ：给自己留几条退路，防止单点失误全盘皆输。

  • K 是旋钮

    ：K 越大越稳但越贵，K 越小越省但越窄，按任务调。

一句话：Beam Search 在"探索广度"和"计算成本"之间取了个平衡。

六、Reflection 与 Self-Correction

再好的计划也可能跑偏。Agent 真正强大的地方，是它会"停下来想"。

  • 执行

    ：按计划走，拿到结果。

  • 失败？

    ：结果不对，或者中途报错。

  • 反思错在哪

    ：是哪一步的判断错了？是计划本身就有漏洞？

  • 重新规划

    ：基于反思修正方案，而不是硬扛。

  • 再执行

    ：带着新计划重新来。

一句话：失败不可怕，可怕的是一条路走到黑。会反思的 Agent，成功率才上得去。

七、动态规划：执行中实时改计划

静态计划一旦定死，中途发现不对也只能将错就错。真实任务充满意外，所以好 Planner 必须边执行边改。

| | 静态计划

|

动态计划
遇偏差

硬着头皮走

|

立即调整路线

| | 遇意外 |

束手无策

|

把意外当输入重排

|

计划的价值不在"不变"，而在"能变"。边走边看，才扛得住现实世界的乱。

八、Planner 的评估指标

怎么判断一个 Planner 好不好？不能只看成功率，还要看"性价比"：

  • 成功率

    ：计划最终能被完整跑通的比例，最核心，但绝不是唯一。

  • Token 消耗

    ：完成同一任务花多少 token，越省越省钱、越快。

  • 工具调用数

    ：调了多少次工具，越少说明规划越精准、越不绕路。

  • 平均步数

    ：从开始到完成走了几步，越短通常越高效。

一个"成功率 100% 但烧了十万 token、调了 fifty 次工具"的 Planner，远不如"成功率 95%、三步搞定"的来得实用。

九、本节实战：旅行规划 Agent

把上面这些规划能力拼起来，就能做一个会"安排行程"的 Agent。它至少具备四种本领：

  • 自动拆预算

    ：按天数、城市、你的偏好，把总预算合理分配到吃住行，不超支也不委屈。

  • 查天气

    ：出发前看目的地预报，雨天自动避开户外景点，帮你挑好天气的日期。

  • 查交通

    ：对比航班、高铁、大巴，按时间和价格排出最优出行组合。

  • 动态修正路线

    ：天气突变、航班取消？Agent 立刻重排计划，而不是让你自己熬夜改行程。

这个 Agent 的特别之处，是把"人肉折腾"变成了"自动出方案"——你只管说要去哪，它把规划全包了。

本课重点回顾

  • 没规划 = 碰运气

    ：复杂任务必须先把全局想清楚。

  • 先拆 DAG

    ：可执行、有依赖、可并行，依赖顺序不能乱。

  • 规划与执行分离

    ：Planner 想，Executor 做，各司其职。

  • 多路径探索

    ：思维树发散，Beam Search 收口，广度与成本平衡

  • 会反思才会强

    ：失败就反思、重新规划，不一条路走到黑。

  • 动态规划

    ：边执行边改，计划能变才好用。

  • 看性价比

    ：成功率之外，还要看 token、步数、工具调用。
